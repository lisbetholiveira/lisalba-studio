# Case Studies

This directory will hold selected Lisalba Studio case studies suitable for public presentation.

## Publication standard

Every case study should include:

1. **Context** — the verified background and communication challenge.
2. **Objective** — what the work was intended to achieve.
3. **Role and scope** — Lisalba Studio's actual contribution and boundaries.
4. **Creative direction** — concept, visual decisions and rationale.
5. **Process** — relevant stages, tools and human decisions.
6. **Selected work** — only assets cleared for public use.
7. **Responsible AI note** — where and how AI contributed.
8. **Outcome** — verified results only; otherwise describe the output, learning or prototype status without implying commercial performance.
9. **Credits and rights** — collaborators, licences and required attribution.

## Status labels

Use one of the following labels prominently:

- **Client project** — only with permission and an accurate description of the relationship.
- **Independent project** — self-initiated work without an external client.
- **Concept project** — fictional or speculative work created to explore a direction.
- **Prototype** — a functional experiment that is not represented as a finished product.

## Planned first test

SOLAE, a fictional concept brand, is planned as the first functional test after the required prompt assistant is installed and validated. Until then, it must not be described as a completed functional case study or a client project.
